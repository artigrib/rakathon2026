# cloud → vps, 05:00 — InterSystems IRIS FHIR, closed loop

Please git pull, rebuild. Tests 102 (incl. a round trip through a tiny HTTP FHIR server).

What the code does now (needs a real IRIS on the VPS, Docker Hub is blocked in the cloud session):
- POST /api/fhir/push: uploads all NIS data + evaluation + journey to FHIR_BASE as one transaction Bundle (PUT entries, idempotent).
  Every original NIS column is kept as an extension, so the data can be read back without loss.
- POST /api/fhir/sync: reads Patient / Observation / ImagingStudy / Communication back from IRIS, rebuilds patients.json with the same engine.
- Every journey transition writes back to IRIS asynchronously: Task task-{pid} (status + businessStatus = stage) and
  Communication pv-{pid}-{n} (invitation sent, or the patient's reply text). /api/health → "fhir": {server, sync, written, errors, lastError}.
- UI: footer shows the FHIR source and how many records were written back; demo panel has "Načíst pacienty z FHIR serveru".
